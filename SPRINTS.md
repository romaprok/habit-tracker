# Habit Tracker — спринти

План задач по спринтах: що робити, в якому порядку і наскільки це складно. Стек, фази й рішення — у [ROADMAP.md](ROADMAP.md).

Поточний спринт: **0 — Фундамент**

## Як читати цей документ

- **Спринти йдуть по черзі, задачі в спринті — зверху вниз.** Після опису задачі вказано, що має бути готове раніше.
- **Кожен спринт — вертикальний зріз.** Він закінчується функцією, яку видно в браузері. Тому фронт і бекенд чергуються: спершу API, потім UI до нього. Фази 1 і 2 роадмапу йдуть паралельно у спринтах 1–3.
- **Тривалість спринту не фіксована.** Спринт закрито, коли пройдено його демо. Після 2–3 спринтів побачиш свою швидкість (скільки SP закриваєш за тиждень) і зможеш планувати точніше.
- **Формат задачі:** `ID` · SP — опис · _після: залежності_

**Треки:** `INF` — інфраструктура, `BE` — бекенд, `FE` — фронтенд, `SH` — спільний пакет `packages/shared`, `EXT` — розширення з беклогу.

**Складність (story points)** — відносна, з урахуванням того, що тема може бути новою:

| SP  | Що означає                                                           |
| --- | -------------------------------------------------------------------- |
| 1   | Дрібниця: все знайоме, одна-дві зміни                                |
| 2   | Невелика задача з однією новою деталлю                               |
| 3   | Середня: кілька файлів або нова бібліотека                           |
| 5   | Велика: нова тема, доведеться читати документацію й експериментувати |
| 8   | Епік: перед стартом розбити на менші задачі                          |

## Definition of Done

Задача закрита, коли:

- `npm run lint` і `npm run typecheck` проходять;
- нова логіка бекенду покрита тестами (починаючи зі спринту 1);
- зміну перевірено вручну — у браузері або через `.http`-файли;
- зміни закомічені з ID задачі в повідомленні, наприклад `BE-05: drizzle schema and seed`;
- задача відмічена в цьому файлі.
